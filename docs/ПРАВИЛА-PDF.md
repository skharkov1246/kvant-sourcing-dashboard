# Правила сборки PDF

Написано после разбора ЛУКОЙЛ-НВН (02.09.2026), где сгенерированный PDF потерял часть
содержимого таблиц. Ошибка была не косметическая: документ ушёл владельцу с обрезанными
ячейками. Соблюдай эти правила при любой генерации PDF в проекте.

## 🔴 Главное: НЕ верстай страницы вручную

**Так делать нельзя:**

```css
.page { height: 194mm; }          /* фиксированная высота страницы */
```
```python
PER = 26                           # ручная нарезка на страницы
for p in range(pages):
    chunk = rows[p*PER : (p+1)*PER]
```

Строки таблицы имеют **разную высоту**: одна ячейка на слово, соседняя — на четыре абзаца.
26 «средних» строк влезают, 26 «высоких» перерастают 194 мм, и всё лишнее браузер молча
обрезает. Ошибка не видна ни в консоли, ни в размере файла — только в готовом PDF.

**Так надо** — таблица течёт сама, движок печати сам разбивает её по страницам:

```css
@page { size: A4 landscape; margin: 9mm 8mm; }
.sec { page-break-before: always; }
.sec:first-child { page-break-before: auto; }

table.t { width: 100%; border-collapse: collapse; table-layout: fixed; }
.t thead { display: table-header-group; }   /* шапка повторяется на каждой странице */
.t tr    { page-break-inside: avoid; }      /* строка не рвётся между страницами */
```

Никаких `height` на контейнере страницы, никакого `overflow: hidden`, никакой нарезки
данных на пачки в Python. Один `<table>` на раздел — сколько бы в нём ни было строк.

## Не обрезай текст в ячейках

**Нельзя:** `E(x["oem"][:150])` — режет фразу на полуслове и теряет смысл.

**Надо** — задать ширины колонок в процентах и дать тексту переноситься:

```css
table.t { table-layout: fixed; }             /* ширины по <th style="width:%"> соблюдаются */
.t td {
  word-wrap: break-word;
  overflow-wrap: anywhere;                   /* длинные парт-номера переносятся */
  vertical-align: top;
}
```

Сумма ширин `<th>` должна давать ровно 100%.

## Инструмент: headless Chromium, не LibreOffice

LibreOffice (`soffice`) в этой среде **не работает** на файлах реального размера —
уходит в таймаут (проверено: 119 с, 499 с, 899 с подряд на книге в 1568 строк).
Не трать на него время.

```bash
/opt/pw-browsers/chromium-1194/chrome-linux/chrome \
  --headless --disable-gpu --no-sandbox \
  --no-pdf-header-footer \
  --run-all-compositor-stages-before-draw \
  --virtual-time-budget=60000 \
  --print-to-pdf=out.pdf file://$PWD/doc.html
```

Ошибки `SSL handshake failed` и `dbus` в выводе — безобидная телеметрия, игнорируй.

## Шрифты и кириллица

```css
body   { font-family: "DejaVu Sans", Arial, sans-serif; }
td.pn  { font-family: "DejaVu Sans Mono", monospace; }   /* парт-номера — моноширинным */
```

DejaVu в образе есть (`fc-list | grep -i dejavu`). Парт-номера моноширинным обязательно:
`64/60082033/4` и `3AXD50000260706` иначе читаются с ошибками.

Широкие таблицы — только `A4 landscape`. Портретная ориентация под 7+ колонок не годится.

## ✅ Проверка обязательна — и не глазами

Готовый PDF проверяй скриптом, а не просмотром пары страниц:

```bash
python3 scripts/pdf_check.py out.pdf --expect-file ids.txt
```

`scripts/pdf_check.py` проверяет три вещи:

1. **Ничего не потеряно** — все строки из `--expect-file` (каталожные номера, ID позиций)
   реально присутствуют в тексте PDF. Это ловит обрезку.
2. **Ничего не вылезло за границы** — элементов с координатами вне `MediaBox` быть не должно.
3. **Нет полупустых страниц** — признак кривого разрыва.

Скрипт возвращает ненулевой код при любой проблеме. Не отдавай файл владельцу,
пока он не проходит чисто.

Дополнительно — визуальный контроль одного разворота:

```bash
chrome --headless --window-size=1090,1180 --screenshot=chk.png file://$PWD/doc.html
```

## Библиотеки

- `pdfminer.six` — извлечение текста и координат для проверки. Ставится через pip.
- `pypdf` в этом образе **сломан** (`ModuleNotFoundError: _cffi_backend` → паника pyo3
  в `cryptography`). Не используй, бери `pdfminer.six`.
- `poppler-utils` (`pdftotext`, `pdfinfo`) не установлен.

## Побочное правило: не обрывай генерирующие скрипты через `| head`

```bash
python3 build_data.py | head -12     # ❌ SIGPIPE убьёт скрипт до json.dump в конце
```

Скрипт умрёт на середине, JSON не запишется, а следующий шаг молча возьмёт **старый**
файл. Ровно так в этой сессии в PDF попали устаревшие цифры. Пиши вывод в файл:

```bash
python3 build_data.py > out.txt 2>&1; head -12 out.txt   # ✅
```
