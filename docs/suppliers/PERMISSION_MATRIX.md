# Матрица прав раздела `/suppliers`

Сопоставлена с фактической системой прав репозитория (`access/acl.js`), а не
взята из шаблона ТЗ. Решение владельца 20.09.2026: вводить постепенно — список,
котировки и цены видны всем входящим; финансы, договоры и контакты закрыты
отдельным правом, по умолчанию ни у кого.

## Как устроены права сейчас

Периметр держит Cloudflare Access: политика по домену почты. Внутри — `access/acl.js`
(канонический экземпляр, копия вшита в `public/_worker.js`, совпадение проверяет
`access/test/acl.test.mjs`). Документ `acl:v1` в Cloudflare KV. Из JWT читаются
три claim'а: `email`, `sub`, `exp`. Групп код не читает.

Гранулярность: **сайт** и **вкладка дашборда**. Скоупа по юрлицу, направлению
или строке данных нет.

Роли в коде по умолчанию — `owner`, `head`, `employee`, и все три получают все
сайты и все вкладки (`access/acl.js:73-91`). Живое состояние в KV из репозитория
не видно.

Проверка настоящая: массивы данных недоступных вкладок вырезаются из HTML до
отдачи (`cutDashboard`), а не прячутся стилями.

## Новые права

**Заведены 20.09.2026** — `access/acl.js`, документ прав поднят до версии 3.
Третья ось рядом с сайтами и вкладками: сайт — всё или ничего, вкладка — про
дашборд, а тут внутри одного раздела надо отделить контакты и деньги от списка
и цен.

Подъём со 2 на 3 выдаёт ролям только `suppliers`. Контакты, финансы и правку
миграция не выдаёт **никому**: разряда `rights` в документах версии 2 не
существовало вовсе, и молча раздать их при подъёме значит открыть то, чего
никто не открывал. Начиная с версии 3 пустой массив понимается буквально —
владелец мог снять право сознательно.

Роль `guest` не получает даже `suppliers`: она заведена как «вошёл, но не
видит», и право по умолчанию отменило бы её смысл.

Выдаются в админке портала: карточка роли — блок «Раздел „Поставщики“»,
карточка человека — «Дополнительно к роли». `/api/rights` возвращает их
полем `rights`.

| право | что открывает | по умолчанию |
|---|---|---|
| `suppliers` | список, карточка, котировки, цены, наличие, история запросов, таблица спецификации | всем ролям, включая `employee` |
| `suppliers_pii` | контакты: ФИО, должность, почта, телефон, каналы связи | **никому**, выдаётся поимённо |
| `suppliers_fin` | договоры, условия оплаты, отсрочка, лимиты, суммы закупок в разрезе юрлиц | **никому**, выдаётся поимённо |
| `suppliers_edit` | корректировки, слияние и разделение сущностей, решения в очереди проверки | **никому**, выдаётся поимённо |

`suppliers_pii` и `suppliers_fin` не входят ни в одну роль по умолчанию — это и
есть исправление положения, при котором роли в коде дают всё всем.

**Банковские реквизиты не показываются никому** и в модель не заводятся:
источника нет, а двойной контроль платежей строится не в дашборде. Если
понадобятся — отдельное решение владельца и отдельный механизм.

**Массовый экспорт контактов запрещён даже с `suppliers_pii`.** Контакт
открывается по одному, в контексте истории. Списком — только по отдельной заявке
с записью в журнал.

## Как обеспечивается

| слой | что делает |
|---|---|
| Cloudflare Access | периметр: кто вообще войдёт |
| `public/_worker.js` | проверка подписи JWT, `rightsFor(acl, email)`, журнал `audit()` |
| `/api/suppliers/*` | **серверная фильтрация ответа**: массив, который читает только закрытая секция, не попадает в ответ — по образцу `cutDashboard` |
| Supabase | `FORCE RLS`, полный `REVOKE` с `anon` и `authenticated`, гранты только `service_role` — по образцу `archive_*` |
| интерфейс | показывает `Нет доступа` вместо значения; это дополнительный слой, а не защита |

**Поле «Нет доступа» не раскрывает значение** ни через API, ни через экспорт,
ни в HTML, ни в клиентском кэше, ни в логах, ни в тексте ошибки. Длина ответа
не должна выдавать наличие значения.

## Обязательные тесты прав

Пишутся вместе с разделом, не после:

1. Каждое право × каждое действие — прямым обращением к API, не только через UI.
2. Горизонтальное повышение: пользователь A не видит данные, доступные только B.
3. Вертикальное: `employee` не получает `suppliers_fin` подменой параметра.
4. Экспорт и выгрузка подчиняются тем же правам, что экран.
5. Кэш ответа не переиспользуется между пользователями с разными правами.
6. Новый чувствительный ресурс закрыт по умолчанию (deny by default).
7. Текст ошибки при отказе одинаков для «нет доступа» и «нет записи».

Существующие тесты доступов (`access/test/`) прогоняются гейтом (`node --test`)
и проверяют совпадение канонического блока прав с копией в воркере — новые права
попадают под ту же проверку автоматически.

## Чего эта матрица не решает

Скоуп по нашему юрлицу и по направлению. Колонка `our_entity_id` закладывается в
таблицы сразу (решение владельца: юрлиц несколько, список не готов), но правило
«человек видит только своё юрлицо» вводится отдельным шагом, когда список
появится. До тех пор `suppliers_fin` — право на все юрлица сразу.
