# Словарь метрик раздела `/suppliers`

Ни одной метрики без числителя, знаменателя, периода, источника и размера
выборки. `success rate`, `reliability score` и подобные ярлыки запрещены.

Машиночитаемая версия — `docs/suppliers/metrics.json`, она же питает подсказки в
интерфейсе. Сегодня словаря метрик в репозитории нет ни в каком виде: определения
живут в коде плюс прозой в `README.md:53-60` и в JS-реестре `METH`
(`templates/dashboard_core.html:1007-1079`, 49 ключей).

## Отзывчивость

### `rfq_response_rate` — доля отвеченных запросов
- **Числитель:** карточки СП-166 поставщика, по которым получен квалифицируемый ответ
- **Квалифицируемый ответ:** входящая активность (`activities.direction = '1'`) по
  сделке карточки **либо** файл поставщика в одном из восьми файловых полей карточки
  (`base/fetch_rfq.py:32-41`), исключая `ufCrm18_1727423346` «Request file» — он наш
- **Знаменатель:** завершённые карточки СП-166 того же поставщика за период
- **Завершённая:** стадия из `GOT`, `REFUSED`, `LOST` либо возраст > 60 дней
- **Исключается:** карточки в стадии `Request Sent` моложе 60 дней — ответ ещё возможен
- **Отказ считается ответом.** Отдельно от `quote_rate`
- **Период / TZ:** календарный, Europe/Moscow
- **Источник:** `rfq`, `activities`
- **Готово?** нет. Требует связи активности с карточкой RFQ (сегодня активности
  привязаны к сделке, `OWNER_TYPE_ID: 2`)

### `quote_rate` — доля запросов с пригодной котировкой
- **Числитель:** карточки, где есть хотя бы одна строка `sup_quote_line` с
  `comparable = true`
- **Знаменатель:** тот же, что у `rfq_response_rate`
- **Готово?** нет: `sup_quote_line` не существует

### `first_response_median` — медиана срока первого ответа
- **Величина:** медиана часов от **фактической отправки** до первой входящей
  активности поставщика
- **Исключается:** карточки без зафиксированной отправки — их не считаем вовсе,
  а не подставляем дату заведения
- **Готово?** нет. **Сегодня подменено:** `days_med` = медиана суток
  `createdTime → movedTime` (`base/suppliers.py:111-117`), то есть срок до
  последнего движения стадии рукой нашего сотрудника. Та же подмена в
  `metrics.py:23-27`. Приложение А ТЗ это прямо запрещает
- **Блокер:** timestamp фактической отправки не хранится нигде

### `quote_completeness` — полнота ответа по строкам
- **Числитель:** строки запроса, на которые получена пригодная строка котировки
- **Знаменатель:** строки запроса, отправленные этому поставщику
- **Готово?** нет: построчной связи «строка RFQ ↔ строка котировки» не существует

## Коммерция

### `selection_rate` — доля выбора
- **Числитель:** карточки с `rfq.chosen = 1` либо стадией `Selected` / `КП получено`
- **Знаменатель:** карточки, где от него получено пригодное предложение
- **Не путать с заказом:** выбор ≠ PO
- **Готово?** частично. Классификация построена на отображаемых названиях стадий
  (`base/suppliers.py:30-34`), которые пишутся в `rfq.stage` из портала
  (`base/fetch_rfq.py:182`) — переименование стадии в Bitrix ломает разряды молча.
  Чинится переходом на `stageId`

### `order_conversion` — доля заказов
- **Числитель:** карточки СП-172 на этого поставщика за период
- **Знаменатель:** случаи выбора (`selection_rate` числитель) за тот же период
- **Готово?** да. Единственный твёрдый денежный факт
- **Источник:** СП-172, `companyId` = поставщик

### `purchased_total` — подтверждённая закупка
- **Величина:** Σ `opportunity` непроигранных карточек СП-172
- **Исключается:** стадии `…:FAIL` — это не контрактная закупка (`main.py:410`)
- **Валюта:** показывается исходная; приведение — отдельное значение с датой и
  источником курса
- **Готово?** да

### `negotiated_discount` — уторгованная скидка
- **Формула:** `(initial − final) / initial` по сопоставимым событиям
- **Не считается**, если начальное и конечное несопоставимы по валюте, количеству,
  базису цены или комплектации. Не «считается приблизительно» — не считается
- **Готово?** нет: `sup_price_event` не существует

### `price_competitiveness` — цена против сопоставимых
- **Только внутри когорты:** один `pn_norm`, одна валюта, один `price_basis`,
  одно `condition`, окно ±90 дней
- **Обязательно показывается:** правило когорты, размер когорты, дата и источник курса
- **Готово?** нет

## Наличие (перенос метода ЛУКОЙЛ)

### `firm_stock_lines` — строк с твёрдым складом
- **Числитель:** `verdict = in_stock` И `stock_grade = твёрдый` И `covers_qty = full`
- **Знаменатель:** строки заявки
- **Замер 13.09.2026:** 93 из 1 642
- **Готово?** данные есть; при переносе в `lib_part_suppliers` теряется `covers_qty`

### `firm_stock_value` — закупка по твёрдым строкам
- **Формула:** `Σ unit_price × qty` по строкам `firm_stock_lines`
- **Замер:** 144 445 USD, шесть валют приведены к доллару по справочному
  межбанковскому курсу на 13.09.2026 (`gt/data/fx_rates.json`)
- **Рядом обязательно:** это НЕ курс сделки

### `covered_volume_value` — подтверждённый объём, любой вердикт
- **Формула:** вся колонка `line_value_full_volume`
- **Замер:** 190 972 USD
- **ЗАПРЕТ:** это **другое число**, не складывать с `firm_stock_value`. Разница
  46 527 USD — объём подтверждён, но отгружать сегодня нельзя. В план поставки
  идёт первое, в оценку потенциала — второе

## Поставки, качество, платежи

`on_time_delivery`, `avg_delay`, `partial_delivery_rate`, `acceptance_rate`,
`claims_rate`, `paid_total`, `open_exposure` — **не определяются и не
показываются.** Фактической даты отгрузки, фактического количества, приёмки,
рекламаций и платежей в доступных данных нет. Интерфейс выводит «Нет данных»
с указанием, какого источника не хватает. Решение владельца 20.09.2026.

Существующий в `contracts.py` показатель «Потери от просрочки» считается по
плановым датам и ставке `CAP_RATE = 0.20`, жёстко зашитой в модуле
(`contracts.py:49`). В раздел `/suppliers` он не переносится: просрочка без
факта приёмки — не факт поставки.

## Отношения

`years_active`, `rfq_volume`, `quote_volume`, `order_volume`, `last_activity` —
считаются прямым счётом по `sup_entity`, `rfq`, `sup_order`. Готовы после
появления ключа поставщика.

## Общие правила показа

1. **Размер выборки рядом всегда.** «В срок: 2 из 2» и «98 из 100» не должны
   выглядеть одинаково. Числитель и знаменатель — не во всплывающей подсказке,
   а в самой строке.
2. **Drill-down обязателен.** Клик по любому числу открывает породившие его
   записи. Метрика без drill-down не показывается.
3. **Шесть состояний вместо цвета:** `0` (событий не было) · `Нет данных`
   (источник пуст) · `Требует проверки` · `Нет доступа` · `Данные на дату …` ·
   `Не применимо`. Цвет не единственный носитель смысла.
4. **Оговорка идёт рядом с числом, а не в сноске**, если число получено
   домножением, экстраполяцией или подстановкой по классу. В заголовок такое
   число не идёт.
5. **Валюта, единица, количество, базис, дата и состояние сопоставимости** —
   при каждой цене, без исключений.
