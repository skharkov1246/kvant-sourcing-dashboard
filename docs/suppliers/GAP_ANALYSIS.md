## Что нельзя подтвердить

- Живое состояние прав в KV `acl:v1`.
- Применена ли `zip/supabase/migrations_rls.sql` вручную к живой базе.
- Реальные объёмы `lib_*` — база в репозитории отсутствует, числа только из прозы.
- Назначение полей «Оплачено» / «Остаток к оплате»: наша оплата поставщику или
  оплата заказчика нам.
- Пересекаются ли множества поставщиков шести реестров и насколько — измерить
  можно только после того, как появится общий ключ.

Семь из двадцати требуют данных, которых в компании нет ни в каком виде
(платежи, фактические поставки, качество, договоры как сущность, наши юрлица,
переговорные раунды). ТЗ §1.7 предписывает показывать по ним «Нет данных», а не
ноль и не оценку модели. Решение владельца от 20.09.2026 это подтверждает.

## Самое дешёвое действие с самым большим эффектом

1. **Пагинация СП-166** — сделано в этом изменении. Без неё всё остальное
   считается по пятидесяти самым старым карточкам.
2. **Ключ поставщика — `rfq.supplier_id` вместо текста.** Одна колонка в SELECT.
   Разблокирует вопросы 1, 3, 8, 9.
3. **Первый ответ из `activities.direction`.** Разблокирует единственную
   метрику отзывчивости, которая сейчас врёт.
4. **Одно правило нормализации артикула с версией.** Разблокирует сопоставление
   цен и вопрос 6.
