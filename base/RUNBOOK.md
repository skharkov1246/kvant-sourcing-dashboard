# Пошаговые пути: что куда добавлять

Шесть сценариев «мне нужно кое-что добавить». Каждый — по шагам, с командой,
проверкой и временем. Если нужного сценария здесь нет, скажите какой — допишу.

---

## 1. Подключить базу данных (делается один раз)

Корпус живёт в сессии агента и исчезает вместе с ней. Чтобы база знаний
осталась навсегда, её надо залить в PostgreSQL (Supabase, где уже живёт база
ЗИП). Два пути — выберите любой.

### Путь А: залить самому, 10 минут

1. Supabase → ваш проект → кнопка **Connect** вверху → вкладка **Session
   pooler**. Скопировать строку вида
   `postgresql://postgres.<ref>:[YOUR-PASSWORD]@aws-<регион>.pooler.supabase.com:5432/postgres`
   и подставить пароль вместо `[YOUR-PASSWORD]`.
   Годится только Session pooler: Direct connection работает по IPv6,
   Transaction pooler (порт 6543) не держит подготовленные запросы.
2. Распаковать присланный архив:
   `tar xzf КВАНТ_база_знаний_выгрузка.tar.gz && cd kb`
3. `export PGURL='<строка из шага 1>'`
4. `sh load.sh` — создаст 12 таблиц и зальёт ~1 062 000 строк. 5–15 минут.
5. Проверка: `psql "$PGURL" -c "select count(*) from kb_catalog"` → должно быть
   153 880.

Нужен `psql`: macOS — `brew install postgresql@16`, Ubuntu —
`sudo apt install postgresql-client`, Windows — через WSL.

### Путь Б: чтобы заливал и поддерживал агент

1. claude.ai/code → окружение этой сессии → **Environment variables** →
   добавить `SUPABASE_DB_URL` со строкой Session pooler
   ([документация](https://code.claude.com/docs/en/claude-code-on-the-web)).
2. Написать в чате «залей базу». Агент выполнит `python base/load_kb.py --dir kb`
   и отчитается числами по каждой таблице.

Переменная хранится в настройках окружения и в репозиторий не попадает.

## 2. Добавить свежие данные из Bitrix

Когда: после волны новых сделок или раз в месяц. Нужен `BITRIX_WEBHOOK_URL`
(уже есть). Порядок важен: каждый шаг опирается на предыдущий.

```bash
python base/export_bitrix.py --since 2026-09-01   # сделки и справочники
python base/fetch_rfq.py                          # запросы поставщикам
python base/collect_attachments.py --new-only     # ссылки на новые вложения
python base/fetch_files.py                        # скачать и разобрать
python base/parse_archives.py                     # распаковать архивы
python base/reparse.py                            # OCR сканов
python base/extract_positions.py                  # номенклатура
python base/file_cards.py                         # карточки документов
python base/kb_catalog.py                         # справочник артикулов
python base/suppliers.py                          # статистика поставщиков
python base/classify_deals.py                     # сегмент, марка, предмет
python base/export_kb.py --out kb                 # выгрузка
python base/load_kb.py --dir kb                   # заливка в базу
```

Время: около часа на месяц новых данных, дольше всего качаются вложения.
Каждый шаг возобновляемый — повторный запуск не перекачивает разобранное.

Проще: сказать в чате «обнови базу за сентябрь» — агент прогонит всё подряд и
пришлёт отчёт с числами.

## 3. Добавить поставщика или марку

**Поставщик** отдельно никуда не добавляется: он попадает в базу с первым
запросом ТКП (смарт-процесс 166). После шага 2 он появится в `kb_suppliers`
со своей историей — сколько запросов, сколько ответов, сколько выборов.

**Марка** заводится в смарт-процессе 176 «Brands» в Bitrix. После
`fetch_brands.py` и `extract_positions.py` она начинает распознаваться в
документах.

Предупреждение: слова-омонимы ломают распознавание. «Test» цеплялся к «Test
port» и выходил на 118 сделок, «Bush» — к втулке, «Ltd» — к любому английскому
названию компании. Такие в справочник лучше не заводить; если завели — скажите,
добавлю в стоп-лист.

## 4. Добавить документы, которых нет в Bitrix

Прайс-лист завода, каталог, КП, пришедшее мимо портала.

Сейчас пути нет: конвейер читает только вложения Bitrix. Нужен импортер,
который берёт папку и прогоняет файлы тем же разбором — текст, карточка,
позиции, справочник. Работы примерно на полдня.

После него путь будет такой:

```bash
python base/import_files.py ~/прайсы --source "BOGE прайс 2026" --supplier "BOGE"
python base/extract_positions.py && python base/kb_catalog.py
```

Скажите — сделаю.

## 5. Добавить справочник на сайт

Страница с поиском по артикулу (`base/kb_page.py`) собирается из базы, поэтому
сначала нужен шаг 1 — база должна где-то жить постоянно.

1. Выполнен шаг 1: данные в Supabase.
2. Агент добавляет workflow, который собирает `public/kb.html` из Supabase и
   выкладывает на Cloudflare Pages — тем же способом, что дашборд.
3. Вход через Cloudflare Access, как на остальных сайтах: отдельных паролей нет.

Без шага 1 страницу можно собрать только вручную в сессии и получить файлом.

## 6. Добавить новый набор данных в репозиторий

По правилам проекта (CLAUDE.md):

1. Положить файл в `data/` или в папку подпроекта.
2. Описать в `data/catalog_notes.json`: что это, откуда, насколько
   чувствительно.
3. `python scripts/build_catalog.py && python scripts/build_index.py`
4. Своя ветка → Pull Request → зелёный гейт → мерж.

Репозиторий публичный: коммерческие и персональные данные в него не кладутся.
