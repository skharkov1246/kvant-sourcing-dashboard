# База знаний по Bitrix24

Здесь лежит конвейер, который вычитывает портал целиком — сделки, запросы
поставщикам, переписку и все вложенные файлы — и складывает прочитанное в
единую базу `kvant.db` (SQLite + полнотекстовый индекс FTS5).

Сама база в репозиторий не коммитится: в ней коммерческие данные, а
репозиторий публичный. Наружу отдаётся выгрузка (`export_kb.py`) — CSV плюс
готовая схема PostgreSQL.

## Порядок запуска

```bash
python base/export_bitrix.py          # сделки, справочники, история стадий
python base/fetch_rfq.py              # запросы поставщикам (смарт-процесс 166)
python base/fetch_brands.py           # справочник марок (смарт-процесс 176)
python base/fetch_chats.py            # переписка по сделкам
python base/collect_attachments.py    # ссылки на вложения (urlMachine)
python base/fetch_files.py            # скачать и разобрать вложения
python base/parse_archives.py         # распаковать архивы, разобрать вложенное
python base/reparse.py                # OCR сканов и картинок
python base/reparse_archive.py        # OCR документов внутри архивов
python base/index_chats.py            # переписку — в общий поиск
python base/extract_positions.py      # номенклатура из документов
python base/file_cards.py             # карточка на каждый документ
python base/kb_catalog.py             # справочник оборудования по артикулам
python base/suppliers.py              # кто отвечает, кто молчит, кто чем возит
python base/loss_reasons.py           # сюжеты провала по текстам (читать по лифту)
python base/match_prices.py           # пары «цена поставщика ↔ наша»
python base/export_kb.py --out kb     # выгрузка наружу
python base/load_kb.py --dir kb       # загрузка в Supabase (нужен SUPABASE_DB_URL)
```

Каждый шаг возобновляемый: повторный запуск не перекачивает то, что уже
разобрано. Портал ограничивает частоту обращений («Method is blocked due to
operation time limit») — модули ждут и продолжают, а не падают.

## Что в базе

| таблица | строка | о чём |
|---|---|---|
| `deals` | сделка | воронка, стадия, исход, сумма, заказчик, ответственный |
| `rfq` | запрос поставщику | кому, на что, чем кончилось |
| `files` | вложение | имя, поле карточки, размер, статус разбора |
| `file_text` | кусок текста | разобранный текст файла, по 40 тыс. знаков |
| `file_cards` | документ | род, сторона, о чём, даты, ИНН, условия, исход |
| `positions` | позиция | артикул, марка, наименование, количество, цена |
| `catalog_items` | артикул | марка, цены поставщика и наши, наценка, исходы |
| `price_pairs` | пара цен | цена поставщика против нашей по одной позиции |
| `supplier_stats` | поставщик | запросы, ответы, молчание, выборы, победы, марки |
| `brand_suppliers` | марка + поставщик | кто реально присылал цены по этой марке |
| `loss_marks` | сюжет сделки | что мешало; читать по лифту, а не по числу |
| `search` | запись | полнотекстовый индекс: файлы, дела, названия, чаты |
| `brands` | марка | справочник марок портала |
| `activities` | дело | звонки, письма, задачи по сделке |

Ключ карточки документа — `sha1` содержимого, а не идентификатор вложения:
32 % разобранных файлов — копии (27 940 из 87 485), и одно и то же ТЗ лежит
в десятке сделок.
Разбор и распознавание делаются один раз, а сделки перечислены в карточке.

## Отчёты

```bash
python base/kb_dash.py  --db base/kvant.db --out kb_report.html   # отчёт по корпусу
python base/kb_page.py  --db base/kvant.db --out public/kb.html   # справочник с поиском
python base/demand.py   --db base/kvant.db                        # спрос и исходы
python base/quote.py    NU2216                                   # карточка сорсинга по артикулу
```

`public/*.html` в репозиторий не коммитится (см. `.gitignore`) — страницы
собираются и выкладываются за Cloudflare Access.
