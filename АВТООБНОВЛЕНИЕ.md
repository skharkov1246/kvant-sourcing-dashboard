# Надёжное автообновление дашборда каждые 2 часа

## В чём проблема
Сборка и деплой исправны (GitHub Actions → Cloudflare Pages). Но **планировщик GitHub (cron)
для приватных репозиториев ненадёжен** — по факту срабатывает ~раз в сутки вместо каждых 2 часов
(GitHub душит scheduled-запуски). Поэтому в воркфлоу добавлен **надёжный внешний триггер**
`repository_dispatch` — его дёргает внешний планировщик. Cron оставлен как резерв.

Нужно один раз настроить внешний планировщик (5 минут). Два варианта — выбери любой.

---

## Что общего: команда, которая запускает пересборку
Любой планировщик должен раз в 2 часа делать такой HTTP-запрос:

```
POST https://api.github.com/repos/skharkov1246/kvant-sourcing-dashboard/dispatches
Headers:
  Authorization: Bearer ГITHUB_TOKEN
  Accept: application/vnd.github+json
  Content-Type: application/json
Body:
  {"event_type":"rebuild"}
```

**GITHUB_TOKEN** — персональный токен GitHub (его создаёшь ты, мне создавать токены нельзя):
- проще всего: github.com → Settings → Developer settings → **Personal access tokens → Tokens (classic)**
  → Generate new token → отметь scope **`repo`** → скопируй токен (`ghp_…`).
- (или fine-grained: доступ только к репо `kvant-sourcing-dashboard`, разрешение **Contents: Read and write**.)

Проверь токен прямо из терминала (должен прийти `204 No Content` и через ~3 мин обновиться сайт):
```bash
curl -i -X POST \
  -H "Authorization: Bearer ghp_ВАШ_ТОКЕН" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/skharkov1246/kvant-sourcing-dashboard/dispatches \
  -d '{"event_type":"rebuild"}'
```

## Вариант A (рекомендую): cron-job.org — без кода, очень надёжно
1. Зарегистрируйся на https://cron-job.org (бесплатно).
2. **Create cronjob**:
   - **URL**: `https://api.github.com/repos/skharkov1246/kvant-sourcing-dashboard/dispatches`
   - **Schedule**: every 2 hours (Custom → `0 */2 * * *`).
   - **Advanced → Request method**: `POST`.
   - **Request body**: `{"event_type":"rebuild"}`
   - **Headers**:
     - `Authorization: Bearer ghp_ВАШ_ТОКЕН`
     - `Accept: application/vnd.github+json`
     - `Content-Type: application/json`
3. Save. Готово — каждые 2 часа дашборд будет гарантированно пересобираться.

(Аналогично можно в UptimeRobot/EasyCron/Make/Zapier — что удобнее.)

## Вариант B: Cloudflare Worker с Cron Trigger (раз уже в Cloudflare)
Надёжный cron внутри той же инфраструктуры. Нужен GitHub-токен (как выше) и `wrangler` (уже есть).

`trigger/wrangler.toml`:
```toml
name = "kvant-dashboard-trigger"
main = "worker.js"
compatibility_date = "2024-11-01"
[triggers]
crons = ["7 */2 * * *"]
```

`trigger/worker.js`:
```js
export default {
  async scheduled(event, env, ctx) {
    await fetch("https://api.github.com/repos/skharkov1246/kvant-sourcing-dashboard/dispatches", {
      method: "POST",
      headers: {
        "Authorization": `Bearer ${env.GH_TOKEN}`,
        "Accept": "application/vnd.github+json",
        "Content-Type": "application/json",
        "User-Agent": "kvant-dashboard-trigger",
      },
      body: JSON.stringify({ event_type: "rebuild" }),
    });
  },
};
```
Деплой:
```bash
cd trigger
npx wrangler secret put GH_TOKEN     # вставить ghp_…
npx wrangler deploy
```

## Ручной запуск в любой момент
- `gh workflow run deploy.yml` (из репозитория), либо вкладка **Actions → Daily dashboard refresh → Run workflow**.
- Либо тот же `curl` из раздела выше.

## Как проверить, что работает
- Вкладка **Actions** в репозитории: должны появляться запуски с событием **`repository_dispatch`** каждые 2 часа.
- На самом дашборде вверху — «Обновлено: …» и «следующее обновление через …» (ближайший 2-часовой слот).
