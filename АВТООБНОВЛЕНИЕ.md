# Надёжное автообновление дашборда (датчик всегда зелёный = данные ≤ 2 ч)

## В чём была проблема
Сборка и деплой исправны (GitHub Actions → Cloudflare Pages). Но **планировщик GitHub (cron)
для приватных репозиториев ненадёжен** — по факту срабатывает раз в 7–11 часов вместо каждых 2
(GitHub душит scheduled-запуски). Поэтому бóльшую часть суток данные честно старше 2 ч и датчик краснел.

## Как решено: САМООБНОВЛЕНИЕ при заходе (основной механизм, уже в коде)
В `public/_worker.js` встроено самовосстановление: **при заходе на сайт, если данные старше 2 ч,
воркер сам триггерит пересборку** (`repository_dispatch`), а страница опрашивает сервер и
перезагружается свежей через ~2–3 мин. Датчик стал **по возрасту данных**: зелёный ≤ 2 ч,
жёлтый «обновляю…» 2–3 ч, красный > 3 ч. Итог: как только кто-то открывает сайт — он становится свежим.

### Что нужно сделать ОДИН раз (иначе самообновление выключено)
Добавить секрет проекта **`GH_DISPATCH_TOKEN`** в Cloudflare Pages:
1. Создай GitHub-токен (мне создавать токены нельзя): github.com → Settings → Developer settings →
   **Personal access tokens → Fine-grained** → доступ только к репо `kvant-sourcing-dashboard`,
   разрешение **Contents: Read and write** → Generate → скопируй (`github_pat_…`).
   (или classic с scope **`repo`** → `ghp_…`).
2. Cloudflare → Pages → проект `kvant-sourcing` → **Settings → Environment variables → Production** →
   Add variable: имя **`GH_DISPATCH_TOKEN`**, значение — токен. **Encrypt**. Save.
3. Redeploy (или дождись ближайшего деплоя). Готово — теперь любой заход на устаревший сайт его освежает.

> Без `GH_DISPATCH_TOKEN` воркер просто отдаёт статику как раньше (самообновление выключено, не ломается).

## Опционально: обновлять и когда НИКТО не заходит
Самообновление срабатывает на заходе. Если нужно, чтобы данные были свежими даже без посетителей
(например, для утреннего открытия), добавь внешний планировщик раз в 2 часа — варианты ниже.
Cron в GitHub Actions оставлен как резерв (срабатывает нерегулярно).

## Что общего: команда, которая запускает пересборку
Любой планировщик должен раз в 2 часа делать такой HTTP-запрос:

```
POST https://api.github.com/repos/skharkov1246/kvant-sourcing-dashboard/dispatches
Headers:
  Authorization: Bearer ГITHUB_TOKEN
  Accept: application/vnd.github+json
  Content-Type: application/json
Body:
  {"event_type":"rebuild"}
```

**GITHUB_TOKEN** — персональный токен GitHub (его создаёшь ты, мне создавать токены нельзя):
- проще всего: github.com → Settings → Developer settings → **Personal access tokens → Tokens (classic)**
  → Generate new token → отметь scope **`repo`** → скопируй токен (`ghp_…`).
- (или fine-grained: доступ только к репо `kvant-sourcing-dashboard`, разрешение **Contents: Read and write**.)

Проверь токен прямо из терминала (должен прийти `204 No Content` и через ~3 мин обновиться сайт):
```bash
curl -i -X POST \
  -H "Authorization: Bearer ghp_ВАШ_ТОКЕН" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/skharkov1246/kvant-sourcing-dashboard/dispatches \
  -d '{"event_type":"rebuild"}'
```

## Вариант A (рекомендую): cron-job.org — без кода, очень надёжно
1. Зарегистрируйся на https://cron-job.org (бесплатно).
2. **Create cronjob**:
   - **URL**: `https://api.github.com/repos/skharkov1246/kvant-sourcing-dashboard/dispatches`
   - **Schedule**: every 2 hours (Custom → `0 */2 * * *`).
   - **Advanced → Request method**: `POST`.
   - **Request body**: `{"event_type":"rebuild"}`
   - **Headers**:
     - `Authorization: Bearer ghp_ВАШ_ТОКЕН`
     - `Accept: application/vnd.github+json`
     - `Content-Type: application/json`
3. Save. Готово — каждые 2 часа дашборд будет гарантированно пересобираться.

(Аналогично можно в UptimeRobot/EasyCron/Make/Zapier — что удобнее.)

## Вариант B: Cloudflare Worker с Cron Trigger (раз уже в Cloudflare)
Надёжный cron внутри той же инфраструктуры. Нужен GitHub-токен (как выше) и `wrangler` (уже есть).

`trigger/wrangler.toml`:
```toml
name = "kvant-dashboard-trigger"
main = "worker.js"
compatibility_date = "2024-11-01"
[triggers]
crons = ["7 */2 * * *"]
```

`trigger/worker.js`:
```js
export default {
  async scheduled(event, env, ctx) {
    await fetch("https://api.github.com/repos/skharkov1246/kvant-sourcing-dashboard/dispatches", {
      method: "POST",
      headers: {
        "Authorization": `Bearer ${env.GH_TOKEN}`,
        "Accept": "application/vnd.github+json",
        "Content-Type": "application/json",
        "User-Agent": "kvant-dashboard-trigger",
      },
      body: JSON.stringify({ event_type: "rebuild" }),
    });
  },
};
```
Деплой:
```bash
cd trigger
npx wrangler secret put GH_TOKEN     # вставить ghp_…
npx wrangler deploy
```

## Ручной запуск в любой момент
- `gh workflow run deploy.yml` (из репозитория), либо вкладка **Actions → Daily dashboard refresh → Run workflow**.
- Либо тот же `curl` из раздела выше.

## Как проверить, что работает
- Открой устаревший сайт (датчик жёлтый/красный «обновляю…») → через ~2–3 мин страница сама перезагрузится и датчик станет зелёным «данные актуальны».
- Вкладка **Actions** в репозитории: при заходе на устаревший сайт появляется запуск с событием **`repository_dispatch`** (тип `rebuild`).
- Датчик вверху дашборда: зелёный = данные ≤ 2 ч, жёлтый = 2–3 ч (идёт обновление), красный = > 3 ч.
