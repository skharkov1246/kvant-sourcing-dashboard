# Автообновление 24/7 + ежедневный отчёт о посетителях

Архитектура (всё в Cloudflare):
- **Pages-воркер** `public/_worker.js` — гейт доступа + при заходе на устаревший сайт сам триггерит
  пересборку + **пишет визиты в KV** (для подсчёта уникальных IP).
- **Планировщик** `scheduler/` — отдельный Cloudflare **Cron Worker**:
  - каждые **6 часов** (:07) → пересборка дашборда (работает, даже когда никто не заходит; реже 2ч —
    чтобы не жечь лимит минут GitHub Actions, актуальность при заходах держит Pages-воркер);
  - каждые **2 часа** (:37) → **алерты**: читает свежие данные и шлёт письмо, если появилось новое
    (новые сделки в реализации по № реализации; крупные ≥ 100 000 € застрявшие открытые сделки с прошедшим сроком);
  - раз в день в **00:05 МСК** → письмо: сколько уникальных IP заходило за прошедший день. Письма — через **Resend**.
- GitHub Actions cron (`7 */2 * * *`) остаётся резервным бэкапом.

Датчик вверху дашборда зелёный, пока данные свежее 2 ч; при простое показывает «обновляю…» и сам
перезагрузит страницу, когда придёт свежий деплой.

## Разовая настройка (~15 минут). Токены вводите вы — мне это делать нельзя.

### 1. GitHub-токен для пересборки
github.com → Settings → Developer settings → **Personal access tokens → Fine-grained tokens** → Generate:
- Repository access: только `skharkov1246/kvant-sourcing-dashboard`;
- Permissions → **Contents: Read and write**;
- Generate → скопируйте `github_pat_…`. (Можно classic-токен со scope `repo`.)

### 2. Resend (отправка письма)
1. Регистрация на https://resend.com (бесплатно ~3000 писем/мес).
2. **API Keys → Create** → скопируйте ключ `re_…`.
3. Отправитель (`from`):
   - быстрый старт: оставьте `onboarding@resend.dev` (письма приходят на ваш же ящик);
   - правильно: **Domains → Add** ваш домен + DNS-записи, затем в `scheduler/wrangler.toml`
     укажите `REPORT_FROM = "Дашборд КВАНТ <dashboard@ваш-домен>"`.

### 3. KV-хранилище визитов
```bash
cd scheduler
wrangler kv namespace create VISITS
```
Скопируйте выданный `id` и впишите в `scheduler/wrangler.toml` (строка `id = "ЗАМЕНИТЬ_НА_ID_KV"`).

### 4. Привязать тот же KV к Pages-проекту (чтобы воркер сайта писал визиты)
Cloudflare Dashboard → **Workers & Pages → ваш Pages-проект → Settings → Bindings → KV namespace bindings → Add**:
- Variable name: **`VISITS`**, namespace — созданный в шаге 3.

Там же (необязательно, для мгновенной пересборки при заходе на устаревший сайт) →
**Variables and Secrets → Add** → **`GH_DISPATCH_TOKEN`** = токен из шага 1.

После добавления биндинга сделайте один redeploy Pages (любой пуш или «Retry deployment»).

### 5. Деплой планировщика
```bash
cd scheduler
wrangler secret put GH_DISPATCH_TOKEN   # вставить токен из шага 1
wrangler secret put RESEND_API_KEY      # вставить ключ из шага 2
wrangler secret put BASIC_AUTH_PASS     # пароль дашборда (тот же, что у Pages) — для чтения данных в алертах
wrangler deploy
```
Готово. В Dashboard → Workers & Pages → **kvant-dashboard-scheduler → Settings → Triggers** будут два крона.

## Как проверить
- **Пересборка**: вкладка **Actions** в GitHub — каждые 2 часа запуски с событием `repository_dispatch`.
  На дашборде датчик «Обновлено … (N мин назад)» зелёный.
- **Отчёт, не дожидаясь ночи** — локальный прогон scheduled-обработчика:
  ```bash
  cd scheduler
  echo 'GH_DISPATCH_TOKEN=...\nRESEND_API_KEY=...' > .dev.vars   # секреты для локального теста
  wrangler dev --test-scheduled
  # в другом окне:
  curl "http://localhost:8787/__scheduled?cron=5+21+*+*+*"
  ```
  (нужно, чтобы в KV уже были визиты за вчера).
- Логи планировщика на бою: `cd scheduler && wrangler tail`.

## Ручной запуск пересборки в любой момент
```bash
gh workflow run deploy.yml
# или repository_dispatch:
curl -X POST -H "Authorization: Bearer github_pat_…" -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/skharkov1246/kvant-sourcing-dashboard/dispatches \
  -d '{"event_type":"rebuild"}'
```

## Приватность
Дашборд — внутренний инструмент за паролем. В KV хранятся только IP заходивших и счётчик заходов за
день (TTL 45 дней, затем авто-удаление). В письме — число уникальных IP, всего заходов и список IP с их
счётчиками. Поллинг свежести (фоновые проверки страницы) в подсчёт не попадает. Иных данных не собираем.
