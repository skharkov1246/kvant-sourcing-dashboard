# Sourcing Analyzer · КВАНТ × Bitrix24

Автономный инструмент: по живому Bitrix24 строит дашборд **анализа работы сорсеров**
из смарт-процесса «Запросы поставщикам» (entityTypeId **166**, воронка **24**).
Считает метрики, генерирует текстовые инсайты (Claude/правила) и собирает HTML-дашборд
в стиле присланного макета (дарк-тема, Archivo/IBM Plex).

## Что показывает (v1 · ядро)
- **KPI-шапка:** всего RFQ за период, отдел Гринёва (172) vs вне отдела, % в работе,
  % КП/выбран из закрытых, % дошедших до ТКП.
- **Нагрузка по сорсерам** + темп/день, **недельная динамика A vs B**, недельные спарклайны.
- **Конверсия по стадиям:** стопка по 7 стадиям, разбивка закрытых (КП / Отказ / Молчание), ср. срок до закрытия.
- **Цепочка «запрос → сделка»:** доводимость до ТКП по сорсерам, исход связанных сделок, какие воронки кормит сорсинг.
- **Покрытие сделок сорсингом:** доля сделок с ≥1 запросом, глубина обзвона (поставщиков/сделку), покрытие по воронкам.

## Быстрый старт для агента

`.agent/README.md` — что где лежит и как проверять; `.agent/manifest.json` — то же
машинно; `data/catalog.json` — каталог всех наборов данных.

## Установка
```bash
cd sourcing-analyzer
python3 -m venv .venv
.venv/bin/python -m pip install anthropic requests pydantic python-dotenv
```

## Настройка (`.env`)
```ini
BITRIX_WEBHOOK_URL=https://<портал>.bitrix24.ru/rest/<id>/<токен>/
ANTHROPIC_API_KEY=            # для инсайтов от Claude; пусто → инсайты по правилам
SOURCING_MODEL=claude-opus-4-8
```
Вебхук создаётся в Bitrix24 (Разработчикам → Входящий вебхук), права: **CRM** + **Пользователи**.

## Запуск
```bash
# дашборд за май 2026 и открыть в браузере
.venv/bin/python main.py --period 2026-05 --open

# только метрики (JSON + сводка), без LLM и HTML
.venv/bin/python main.py --period 2026-05 --dry-run

# произвольный диапазон, инсайты по правилам
.venv/bin/python main.py --period 2026-04-01:2026-05-15 --no-llm
```
Результат: `reports/dashboard_<период>.html` и `reports/metrics_<период>.json`.

**Флаги:** `--period` (`YYYY-MM` | `YYYY-MM-DD:YYYY-MM-DD` | `YYYY-MM-DD`; по умолчанию — с 01.05.2026),
`--no-llm`, `--dry-run`, `--out <каталог>`, `--open`, `--max-deals N` (лимит для теста),
`--as-of YYYY-MM-DD` (переопределить «сегодня»). Жёсткий пол по дате создания — **01.01.2026**.

## Определения метрик
- **Блок A** — сотрудники отдела 172 («Отдел поиска поставщиков», глава Artem Grinev); **блок B** — все прочие.
- **Стадии → бакеты** (`stages.py`): Новый, Отправлен, Переписка/цена, КП/выбран (Selected+КП получено),
  Отказ, Молчание (ответ не получен в срок), Прочее. `closed = КП + Отказ + Молчание + Прочее`.
- **Ср. срок** — `movedTime − createdTime` по закрытым, дни.
- **ТКП выдано+** — сделка (`parentId2`) в статусе исполнения/выиграна. Эвристика по имени стадии +
  семантике в `stages.py` (`_TKP_POS` / `_TKP_NEG` / `WON`). При желании сузить до WON — правится там же.
- **Покрытие** — сделки периода (все воронки) с ≥1 связанным RFQ; глубина = RFQ на покрытую сделку.

## Проверки

```bash
python -m pytest -q                          # тесты ядра
ruff check .                                 # ошибки кода
python scripts/build_catalog.py --check      # каталог данных актуален
python scripts/validate_dashboard.py public/index.html   # собранный дашборд годен к деплою
```

Те же проверки выполняет `.github/workflows/gate.yml` на каждый PR, а валидация
собранного HTML стоит барьером перед деплоем: сломанный или пустой дашборд
на сайт не уезжает.

## Архитектура
```
config.py          конфиг и доменные константы (отдел 172, пол периода)
bitrix_client.py   REST-клиент: троттлинг, пагинация, СП-166, отделы, сделки, кэш справочников
period.py          разбор периода + недельные бакеты (Пн–Вс)
stages.py          мэппинг стадий СП-166 + классификатор ТКП
metrics.py         движок метрик (чистые функции) → dict
insights.py        гибрид: правила + Claude Opus 4.8 (adaptive thinking, кэш system)
templates/dashboard_core.html   шаблон (данные через window.__DATA__/__INSIGHTS__)
dashboard.py       подстановка metrics+insights → HTML
main.py            CLI-оркестратор + проверка достаточности данных
tests/             фикстура синтетических данных Bitrix и тесты ядра
scripts/validate_dashboard.py   проверка собранного HTML перед деплоем
scripts/build_catalog.py        каталог данных → data/catalog.json
```
