# CLAUDE.md — правила работы над проектом

Этот файл читают агенты Claude Code, работающие в репозитории. Соблюдай его.

## Что это за проект
**Sourcing Analyzer (КВАНТ × Bitrix24)** — внутренний дашборд анализа работы сорсеров.
По живым данным Bitrix24 (смарт-процесс «Запросы поставщикам», entityTypeId 166) считает
метрики, генерирует HTML-дашборд и деплоит его на Cloudflare Pages за Basic Auth.

- Точка входа: `main.py` → тянет данные из Bitrix → модули метрик → рендер HTML.
- Модули расчёта: `metrics.py`, `company.py`, `advisor.py`, `reps.py`, `kam.py`,
  `contracts.py`, `insights.py`, `stages.py`, `period.py`.
- Вёрстка: **`templates/dashboard_core.html`** — один самодостаточный HTML-шаблон
  (встроенные CSS+JS, данные подставляются плейсхолдерами `__..._JSON__`). 9 вкладок.
- Сборка HTML: `dashboard.py`.

## 🔴 Критические правила (нарушение = сломанный прод или сожжённый лимит)

1. **НИКОГДА не коммить и не пушь напрямую в `main`.** Только: своя ветка → Pull Request →
   мерж. Ветка: `git checkout -b feature/<короткое-описание>`.
   **Мерж PR агент выполняет сам** (распоряжение владельца, 06.08.2026: «мерджи всегда сам») —
   но ТОЛЬКО после обязательной локальной проверки (см. п. 3: браузерный тест вёрстки /
   dry-run логики). Ревью владельца — по его желанию, не блокер.
2. **Каждый мерж в `main` = мгновенный деплой на живой сайт + полная сборка ~8 мин
   на GitHub Actions.** Лимит Actions — 2000 мин/мес и легко выгорает. Поэтому:
   - не мержить по мелочи много раз подряд — батчь изменения в один PR;
   - никаких циклов «пуш за пушем»;
   - не гоняй пересборку ради проверки — тестируй локально (см. ниже).
3. **Тестируй ДО пуша, а не «залил в main и смотрю на сайте».**
   - Вёрстка/UI: рендерь `templates/dashboard_core.html` с моковыми данными в headless-браузере
     (Playwright/Chromium) и делай скриншот. Проверяй: нет JS-ошибок, нет горизонтального
     оверфлоу, вкладки открываются.
   - Логика/метрики: `python main.py --dry-run` (нужен `BITRIX_WEBHOOK_URL` в `.env`) —
     считает метрики и печатает сводку без деплоя.

## ⛔ Что НЕ трогать без явной отдельной задачи
- `.github/workflows/` — CI и деплой.
- `scheduler/` и `public/_worker.js` — автообновление (Cloudflare Cron Worker) и гейт доступа.
  Расписание пересборки намеренно раз в 6 ч — не возвращать к 2 ч (это жжёт лимит минут).
- Секреты и `.env` (в git не коммитить — он в `.gitignore`).
- `data/chat_snapshot.json` — им управляет бот (scan.yml), руками не редактировать.

## Локальный запуск
```bash
python3 -m venv .venv
.venv/bin/pip install anthropic requests pydantic python-dotenv
# для реальных данных — создать .env с BITRIX_WEBHOOK_URL=https://<портал>.bitrix24.ru/rest/<id>/<токен>/
.venv/bin/python main.py --period 2026-05 --dry-run     # метрики без деплоя
```
Для правок только вёрстки данные Bitrix не нужны — рендерь шаблон на моковых данных.

## Стиль работы
- Коммиты — понятными сообщениями на русском, по-смыслу (что и зачем).
- Правки вёрстки держи в стиле окружающего кода (плотный inline CSS/JS шаблона).
- После нетривиальной правки — прогони визуальную проверку в браузере перед PR.
- Если правка затрагивает деплой/планировщик/секреты — сначала спроси владельца.

## Стиль всех документов для заказчиков и владельца (ТКП, КП, письма, отчёты)
Распоряжение владельца, 04.09.2026: строгий текст в Times New Roman, «стиль ведомости, но на
белой бумаге». Чёрный текст на белом, тонкие чёрные линии таблиц, обычное начертание —
без цветных плашек, тегов-статусов, жирных выделений в строках, маркированных списков с
«жирными» лид-инами и прочих признаков сгенерированного текста. В ТКП заказчик должен
прямо видеть, что предлагается оригинал либо изделие, максимально приближенное к оригиналу
(первой строкой — оригинал, далее — рекомендуемый вариант). Правила и каркас —
навык `tkp-vedomost` (см. ниже); печать в PDF — `pdf-analysis/scripts/html2pdf.sh`.

## Навыки в репозитории
Лежат в `.claude/skills/`, подхватываются автоматически — не изобретай заново:
- **`supplier-rfq`** — кампания запросов ТКП поставщикам через Bitrix24.
- **`pdf-analysis`** — чтение и OCR сканированных PDF (ТЗ, ТКП, счета), сравнение
  двух редакций документа, сборка отчёта обратно в PDF. Готовые скрипты:
  `scripts/setup.sh` (poppler + tesseract + pypdf), `scripts/ocr_pdfs.sh` (OCR папки,
  ~1,2 с на страницу), `scripts/diff_docs.py` (дифф двух OCR-текстов),
  `scripts/html2pdf.sh` (печать HTML в PDF headless-хромом),
  `templates/report_a4.html` (каркас A4-отчёта).
  Владелец просит материалы в PDF — отчёты собирай этим навыком.
- **`tkp-vedomost`** — обязательный стиль всех ТКП/КП/документов: Times New Roman, стиль
  ведомости на белой бумаге, без выделений; принцип «оригинал или максимально приближенное».
  Каркас: `templates/tkp_a4.html`.
