# Доступы по заявке — тестовый контур

Персональные доступы к дашборду вместо одного общего пароля: человек запрашивает доступ,
владелец подтверждает письмом, в заявке указаны **конкретные вкладки**.

**На прод ничего не выкачено.** Прод-гейт `public/_worker.js` (Basic Auth) не тронут,
workflow'ы не тронуты, шаблон дашборда не тронут. Всё живёт в папке `access/` и запускается
локально.

## Запуск контура

```bash
node access/devserver.mjs          # http://127.0.0.1:8788
node access/devserver.mjs --reset  # начать с чистого листа
node --test access/test/flow.test.mjs   # сквозной автотест (13 проверок)
```

Что где:

| адрес | что это |
|---|---|
| `/` | сам дашборд, порезанный по правам вошедшего |
| `/access/` | форма заявки + вход по ссылке из почты |
| `/access/outbox` | «почтовый ящик» контура — все письма со ссылками (только в тесте) |
| `/access/basic` | аварийный вход владельца по логину/паролю (`kvant` / `contour`) |
| `/admin` | админка: заявки, пользователи, вкладки, отзыв |

Контур подставляет `public/index.html`, если он собран (`python main.py`), иначе строит
моковую сборку из `templates/dashboard_core.html`. С моками цифры на вкладках пустые —
это нормально, контур проверяет доступы, а не метрики. Для правдоподобного вида положите
настоящий `public/index.html` и перезапустите с `--reset`.

## Сценарий целиком

1. **Заявка.** `/access/` → почта, имя, подразделение, **галочки вкладок**, обоснование.
2. **Письмо владельцу** со сводкой заявки и ссылкой подтверждения (живёт 14 дней).
3. **Решение.** По ссылке открывается страница: галочки уже проставлены по заявке, можно
   снять лишние, выбрать срок (90 / 180 / 365 дней / бессрочно) → «Выдать доступ» или «Отказать».
4. **Письмо заявителю** с одноразовой ссылкой входа (сутки). Пароля нет вообще.
5. **Вход** ставит подписанную куку на 30 дней. Права читаются из хранилища при каждом
   запросе — отзыв срабатывает мгновенно, перелогин не нужен.

Владелец заходит первый раз просто: `/access/` → своя почта → ссылка из письма. Учётка
владельца (`OWNER_EMAIL`) создаётся автоматически с правами админа. Логин/пароль остаются
как аварийный вход, чтобы не запереть себя снаружи.

## Что именно закрывают права

Вкладка без права не просто спрятана — на сервере из HTML вырезается кнопка, панель и,
главное, **массив данных**: в исходном коде страницы его нет. Проверяется автотестом
(маркеры `MOCK-*` не должны встречаться в ответе).

Вместо вырезанных данных подставляется пустышка `__kvNoData()`: шаблон местами читает
данные сразу при загрузке и на голом `null` падал бы вместе с переключателем вкладок.

**Точность ACL — важное ограничение.** Дашборд отдаёт данные девятью массивами, а вкладок
десять, поэтому две пары делят один массив:

| вкладки | общий массив |
|---|---|
| Реализация ↔ Поставщики | `__CONTRACTS__` |
| Пульс компании ↔ Когорты | `__COMPANY__` |

Выдача одной вкладки из пары технически открывает данные второй в исходном коде страницы
(в интерфейсе второй вкладки не будет). Это написано прямо в форме заявки и на странице
решения. Чтобы разделить пары по-настоящему, нужно разнести данные на отдельные массивы
в `dashboard.py` и `templates/dashboard_core.html` — это правка прода, поэтому она отложена
до отдельного решения владельца.

## Устройство

| файл | назначение |
|---|---|
| `gate.js` | вся логика: маршруты, токены, ACL, резка HTML, письма |
| `_worker.js` | точка входа Cloudflare Pages (тонкая обёртка, fail-closed) |
| `contour.mjs` | подпорки контура: KV на файле, ASSETS на папке, моки |
| `devserver.mjs` | локальный сервер контура |
| `test/flow.test.mjs` | сквозной автотест |
| `wrangler.toml` | конфиг **отдельного** проекта Pages `kvant-sourcing-test` |

Хранилище — Cloudflare KV: `u:<почта>` пользователь, `r:<id>` заявка, `n:<id>` погашенная
ссылка входа, `rl:` счётчик частоты, `m:` ящик писем контура.

Подписи (кука сессии, ссылка подтверждения, ссылка входа) — HMAC-SHA256 на секрете
`SIGN_KEY`, без внешних библиотек. Ссылка входа одноразовая и на сутки; ссылка
подтверждения — на 14 дней и гаснет после решения.

## Почта

`MAIL_PROVIDER`:

- `log` — контур: письмо кладётся в `/access/outbox` и печатается в консоль. Ничего не уходит наружу.
- `resend` — боевой режим, нужны `RESEND_API_KEY` и `MAIL_FROM` с подтверждённым доменом.

Провайдер выбран так, чтобы контур гонялся без единого внешнего сервиса. Какой сервис
рассылки использовать на бою — решение владельца; вместо Resend подключается любой
HTTP-API правкой одной функции `sendMail`.

## Когда решим выкатывать

1. Завести отдельный проект Pages `kvant-sourcing-test` и KV-namespace (команды — в шапке
   `wrangler.toml`), выкатить туда и погонять на живых данных.
2. Подключить почтовый провайдер и проверить, что письма доходят.
3. Только после этого — заменить прод-гейт: положить `access/gate.js` рядом с
   `public/_worker.js` и переключить его на `handle()`. Прод-пароль (`BASIC_AUTH_PASS`)
   остаётся аварийным входом.

Переменные окружения проекта: `OWNER_EMAIL`, `SIGN_KEY` (секрет), `BASIC_AUTH_USER`,
`BASIC_AUTH_PASS` (секрет), `MAIL_PROVIDER`, `RESEND_API_KEY` (секрет), `MAIL_FROM`,
`SITE_URL`, `CONTOUR` (`test` — включает пометку контура и ящик писем; на бою НЕ задавать).

## Панель доступов (с 07.09.2026)

Кто вообще войдёт — решает Cloudflare Access (политика по домену почты). Что человек
увидит внутри — решает панель по адресу **`/admin`** на портале. Открыта только владельцу.

| элемент панели | что делает |
|---|---|
| таблица людей | почта, роль, сколько выдано сайтов и вкладок, личные добавки, последний вход |
| «Роль для новых» | какая роль достаётся тому, кто вошёл впервые |
| поле «завести заранее» | добавить человека до его первого входа |
| карточки ролей | галочки сайтов и вкладок; правка роли действует на всех её носителей |
| «настроить» у человека | точечные добавки СВЕРХ роли и заметка (например, срок подряда) |
| «снять с учёта» | убрать человека из списка; права возвращаются к роли для новых |

Все правки сохраняются сразу, отдельной кнопки «применить» нет. Хранилище — Cloudflare KV,
один документ `acl:v1` в привязке `ACL`, а при её отсутствии — в уже привязанной `VISITS`.
Права читаются на каждом запросе, поэтому отзыв срабатывает немедленно, без перелогина.

Роли при первом запуске: владелец, руководитель, сотрудник (по умолчанию — всё),
сорсинг, КАМ, инженер, гость (ничего). Набор правится в панели.

**Страховка от самозапирания.** Почты из переменной `ADMIN_EMAILS` (по умолчанию
`stepan@kvantpro.com`) получают полные права и признак админа независимо от хранилища.

### Плитки портала

Три библиотеки оборудования и четыре остальных ресурса:

| плитка | право | адрес |
|---|---|---|
| Дашборд сорсинга | `dashboard` | `/dashboard` на портале |
| ГШО — горно-шахтное оборудование | `zip` | kvant-zip.pages.dev |
| ГТУ — газотурбинные установки | `gt` | kvant-zip.pages.dev/gt/ |
| ГПУ — газопоршневые установки | `gpu` | kvant-gpu.pages.dev |
| ОВЭ-75 | `ove` | kvant-ove.pages.dev |
| Гидрометаллургия | `gidromet` | kvant-gidromet.pages.dev |
| Базовый проект ГОКа | `gok` | kvant-gok.pages.dev |

ГШО и ГТУ живут в одном проекте Pages, но это две плитки с разными правами: гейт
`zip/site/_worker.js` спрашивает право `gt` для раздела `/gt/` и `zip` для всего прочего.
Идентификатор `zip` оставлен после переименования «Базы ЗИП» в ГШО, чтобы не отнять
доступ у тех, кому он уже выдан; документ прав поднят до версии 2, и всем, у кого был
`zip`, миграция добавляет `gt`.

### Что чем закрывается

| слой | файл | что решает |
|---|---|---|
| вход | `access/cfaccess.js` | подпись Cloudflare Access — пускать ли вообще |
| права | `access/acl.js` | сайты и вкладки человека; резка дашборда на сервере |
| право на сайт | `access/siterights.js` | гейт чужого сайта спрашивает портал по `/api/rights` |

Канонические экземпляры лежат в `access/`, копии блоков между маркерами `BEGIN`/`END`
вшиты в гейты (Pages в advanced-режиме не умеет импортировать соседние файлы).
Расхождение копий ловят тесты.

Вкладка без права вырезается из HTML вместе с массивом данных — в исходном коде страницы
её цифр нет. Ограничение по парам вкладок описано выше и продублировано в самой панели.

Гейты пяти остальных сайтов спрашивают права у портала, пересылая подпись входа сотрудника;
общих секретов между проектами нет. **Если портал недоступен, сайт открывается** — терять
разграничение внутри уже закрытого периметра лучше, чем перекрывать работу всей компании.
Проверку можно выключить переменной `SITE_RIGHTS=off`.

### Проверки

```bash
node --test access/test/cfaccess.test.mjs     # вход: подпись, срок, издатель, копии в гейтах
node --test access/test/acl.test.mjs          # роли, добавки, резка вкладок
node --test access/test/siterights.test.mjs   # право на сайт, поведение при сбое портала
node --test access/test/portal.test.mjs       # сквозная: портал, дашборд, админка на боевом _worker.js
```

Все четыре набора гоняет гейт `.github/workflows/gate.yml` на каждый PR.

## Периметр — Cloudflare Access (с 07.09.2026)

Все шесть сайтов закрыты одним приложением Cloudflare Access «Портал КВАНТ» (шесть адресов
pages.dev, одна политика допуска по почте, вход по разовому коду). Паролей на сайтах нет.
Каждый гейт `_worker.js` перепроверяет подпись входа помощником из `access/cfaccess.js`
(копии сверяет `access/test/cfaccess.test.mjs`), чтобы адреса предпросмотра не обходили
периметр. Портал с плитками сайтов отдаёт `public/_worker.js` на `/`, дашборд — на `/dashboard`.
Контур, описанный выше (заявки, права по вкладкам), — следующий слой поверх Access.
