историю коммитов. Этот файл фиксирует, что именно открыто, что уже исправлено
и какие решения остаются за владельцем.

## Что исправлено в этом изменении

- Из индекса git убран `.wrangler/cache/` — он раскрывал `account_id` Cloudflare
  и e-mail владельца; добавлен в `.gitignore`.
- Убраны мёртвые артефакты `scripts/_coll_*.json`.
- В CI-гейт добавлен поиск секретов: вебхуки Bitrix с токеном, ключи Anthropic,
  GitHub, AWS и приватные ключи не пройдут в PR.
- Каждый набор данных получил оценку чувствительности в каталоге, поэтому новый
  конфиденциальный файл виден сразу, а не через год.

Важно: удаление файла из рабочего дерева **не удаляет его из истории**. Всё
перечисленное выше остаётся доступным в старых коммитах, пока история не очищена.

## Решения владельца

Ни одно из этих действий не выполнено автоматически: каждое либо ломает
работающий сайт, либо требует доступа, которого у агента нет.

1. **Закрыть репозиторий или вынести данные.** Репозиторий сделан публичным ради
   бесплатных минут GitHub Actions. Замер по Actions API за 30 суток (08.08–07.09.2026):
   **4 157 минут, 568 прогонов**, из них пересборка дашборда — 3 517. Лимит для
   приватных репозиториев: 2 000 мин/мес на GitHub Free, 3 000 на Pro; сверх лимита
   Linux 2-core стоит $0,006/мин, а без привязанной карты прогоны просто встают.

   Две правки от 07.09.2026 срезали расход примерно до **2 100 мин/мес**: резервный
   крон больше не дублирует внешний планировщик (PR #195), а пересборка дашборда
   запускается только от файлов, которые на него влияют (PR #198) — 11 коммитов
   из 168 вместо 123.

   Варианты дальше: приватный репозиторий с оплатой минут; вынос данных в приватный
   репозиторий-спутник или Cloudflare R2 с подгрузкой в CI по секрету.
   *Рекомендация: вынести данные, репозиторий кода оставить публичным. Закрытие само
   по себе не убирает данные из истории 525 коммитов и не влияет на пункт 2.*

2. **Ограничить доступ к базе ЗИП.** Заготовка — `zip/supabase/migrations_rls.sql`,
   два варианта с описанием последствий. Сейчас не применено, потому что сайт
   пишет в базу тем же ключом и запрет записи его сломает.
   *Рекомендация: вариант A сразу, вариант B — при следующей правке сайта.*

3. **Очистить историю и отозвать учётные данные.** После выноса данных —
   `git filter-repo` по перечисленным путям, затем пересоздать вебхук Bitrix.
   Паролей на сайтах больше нет: вход держит Cloudflare Access (`access/cfaccess.js`),
   отзывать нечего. Переписывание истории затрагивает 525 коммитов из 570 — самый
   ранний с конфиденциальными путями — и меняет SHA всем веткам и открытым PR:
   нужно согласовать момент и предупредить всех, у кого есть клоны.

## Куда класть секреты

Только в GitHub Secrets (Settings → Secrets and variables → Actions) и в секреты
Cloudflare Pages. В коде, в комментариях к workflow и в данных — никогда.
Локально — в `.env`, который в `.gitignore`.
