# ADR-0002 · Offline-first: события + outbox вместо CRUD

**Статус:** принято · **Дата:** 2026-07-28

## Контекст
Склад — среда без стабильной связи: бетон, металлические стеллажи, холодильные
камеры, подвалы. Требование заказчика — «система никогда не должна падать».
Работа кладовщика не может зависеть от доступности сервера, а уже выполненная
работа не может теряться ни при каких обстоятельствах.

## Решение
Устройство — источник истины на время смены. Любое действие пишется в локальный
SQLite синхронно, до отправки. Изменения представлены **неизменяемыми событиями**
с `client_event_id` (UUIDv7), которые доставляются фоновым outbox-воркером.
Сервер применяет события идемпотентно и сворачивает их в состояние проекцией.
Ни одно действие UI не ждёт сеть.

## Последствия
- Полная работоспособность офлайн, включая многосменную автономность.
- Повторная доставка безопасна; батч не падает целиком — ответ по каждому событию.
- Бесплатно получаем аудит и возможность воспроизвести сессию шаг в шаг.
- Продолжение сессии на другом устройстве — доигрывание лога.
- Цена: сервер обязан поддерживать проекцию и держать её единственным местом
  истины; логика сворачивания дублируется в ядре клиента и должна быть покрыта
  общими тестами на одинаковый результат.
- Хранилище растёт: события не удаляются.

## Отвергнутые варианты
- **CRUD с PUT текущего состояния.** Проще, но при обрыве даёт либо потерю, либо
  дубль; частичная доставка оставляет неконсистентное состояние; аудита нет.
- **CRDT.** Решает конфликты автоматически, но здесь конфликты редки и должны
  разбираться человеком (расхождение в габаритах — повод для проверки, а не для
  автослияния). Сложность не окупается.
- **Онлайн-режим с кэшем.** Первый же холодильный склад показывает, что кэш
  превращается в основной режим работы — лучше сразу проектировать под него.
