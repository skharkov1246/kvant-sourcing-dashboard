# Реализация как процесс

Решение владельца 19.10.2026: вкладка «Реализация» — инструмент руководителя
реализации, а не отчёт. Каждое число отвечает на вопрос «что сделать и кто».

## 1. Единица управления

- **Заказ поставщику (СП-172)** — единица исполнения: у него срок клиента, план и
  факт по каждой точке, хозяин (ОСС заказа — «Deal support specialist»).
- **Сделка воронки реализации (кат. 0)** — единица обязательства перед клиентом:
  договор, сумма, закрытие. У сделки может быть несколько заказов.

## 2. Фазы — по фактам, а не по стадии (`lifecycle.phase`)

| фаза | условие (по полям заказа) |
|---|---|
| размещение | нет «Оплачено поставщику, %» и нет «Production confirmation» |
| производство | оплата > 0 или подтверждение есть, «Supplier Shipment Date, actual» пусто |
| в пути | отгрузка поставщика (или приход на склад) есть, «Customer delivery date, actual» пусто |
| закрытие | доставлено, нет УПД (дата или файл) или «Payment Order (client)» |
| гарантия | доставлено, УПД и платёж есть, срок гарантии идёт |

Стадии СП-172 у разных воронок свои и часто отстают от факта — фазу по имени
стадии не определять. Провал заказа — по **семантике** стадии (F), а не по
суффиксу «:FAIL»: свои стадии провала `UC_*` иначе считаются живыми.

## 3. Очередь «что делать» (`lifecycle.EXC`)

Порядок важности: срок клиента сорван → под риском (≤ 14 дн., поставщик не
отгрузил) → плановая отгрузка прошла без факта → план доставки позже срока →
срок оплаты клиента прошёл без платёжки → нет УПД через 14 дн. → все заказы
закрыты, сделка открыта → нет заказа неделю → ведёт уволенный → нет срока
клиента → заказ закрыт без даты доставки.

Хозяин: ОСС заказа → ОСС сделки (поле сделки, не склейка ОСС заказов) →
ответственный сделки; «уволен» — по подписи показанного хозяина. Доставленный, но не
закрытый заказ — **не просрочка**, а закрытие (УПД, оплата). Закрытие ждём только
у живого заказа и только по доставкам за `CLOSE_DAYS`: платёжка клиента стала полем
в июле 2025, старые доставки без файла — пробел учёта, а не долг. Вселенная очереди —
заказы известных сделок без проигранных; у выигранной закрытой сделки сроки заказов
уже не отклонения. Прогноз не отгруженного заказа считается от «не раньше сегодня».

## 4. Пороги — таблицей (правило 4)

`RISK_DAYS = 14`, `UTD_GRACE = 14`, `PAY_GRACE = 30`, `CLOSE_DAYS = 365`, `SUP_MIN = 3`,
`WARRANTY_MONTHS = 12` — **допущение** до решения владельца (в договорах
встречается 12 мес. от ввода, не больше 18 от поставки, и 24 мес.). Меняешь
порог — сначала замер (холостой прогон, зонд), потом правка, в PR — «ожидается:».

## 5. Чего в портале нет (не придумывать — «Нет данных» + откуда должно прийти)

- рекламаций и актов о дефектах — гарантийные случаи не видны;
- фактов оплаты в деньгах (Р-2): платёжка клиента — только как файл;
- срока гарантии в карточке; даты ввода в эксплуатацию;
- товарных строк заказов — частичную поставку не отследить.
