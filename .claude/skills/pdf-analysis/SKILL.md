# Работа с PDF: OCR, сравнение, отчёт в PDF

Проверено на пакете ТЗ «Норильский никель» (5 файлов, 66 страниц сканов, сентябрь 2026).
Полный цикл — от голого контейнера до готового PDF-отчёта — занимает ~10 минут,
из них 4–6 минут OCR.

## 0. Правило номер один

Сначала проверь, есть ли в PDF текстовый слой. Не трать страницы визуального чтения
на документ, из которого текст достаётся за секунду:

```bash
pdftotext -l 3 file.pdf - | head -20      # пусто → это скан, нужен OCR
```

Визуальное чтение (`Read` с параметром `pages`) стоит ~1–2 тыс. токенов на страницу.
OCR всего документа стоит ноль токенов. Читай глазами только те страницы, где
OCR дал сомнительный результат или где важна подпись/печать/чертёж.

## 1. Установка (контейнер приходит пустым)

```bash
bash .claude/skills/pdf-analysis/scripts/setup.sh
```

Ставит `poppler-utils` (pdftotext, pdftoppm, pdfinfo), `tesseract-ocr` + русский
языковой пакет, `pypdf` и `cffi`.

Грабли:
- `apt-get install` без `apt-get update` падает с 404 — версии в индексе протухли.
- `pip install pypdf` без `cffi` даёт `PanicException` в `cryptography` при импорте.
- Инструмент `Read` для PDF требует `pdftoppm`; без poppler он отвечает
  «pdftoppm is not installed», а не «файл не читается».

## 2. OCR всей папки

```bash
bash .claude/skills/pdf-analysis/scripts/ocr_pdfs.sh <папка-с-pdf> <папка-вывода>
```

Рендер 150 dpi + `tesseract -l rus --psm 6`, 4 файла параллельно, `OMP_THREAD_LIMIT=1`.
На выходе — по одному `.txt` на документ с маркерами `===== PAGE NN =====`.

Цифры для планирования: 109 страниц ≈ 3 минуты. Одна страница ≈ 1,2 с.
Не запускай `rus+eng` и не поднимай dpi выше 150 без нужды — на многоязычных
моделях время растёт кратно, качество на русских ТЗ не меняется.

## 3. Сравнение двух редакций

```bash
python3 .claude/skills/pdf-analysis/scripts/diff_docs.py a.txt b.txt            # полный дифф
python3 .claude/skills/pdf-analysis/scripts/diff_docs.py a.txt b.txt --changes  # только вставки/удаления
```

Скрипт режет текст на предложения, снимает колонтитулы вида `113W_000_3494767_27`
и кавычки, сравнивает по `difflib.SequenceMatcher`. Режим `--changes` показывает
только `insert`/`delete` — это и есть реально добавленные и убранные требования;
`replace` в 90 % случаев — переносы строк и шум OCR.

Грабли:
- Не нормализуй регистр через `tr 'A-ZА-Я' 'a-zа-я'` — `tr` побайтовый и рвёт UTF-8
  в мусор. Только Python.
- OCR путает цифры (`0,001` → `0,004`), латиницу и кириллицу (`Deutz` → `Беиы`,
  `Dana` → `Рапа`), `W` → `\/`. **Любое расхождение по цифре или по требованию,
  которое пойдёт в отчёт, проверяй глазами** на исходной странице:
  найди номер страницы через `awk '/===== PAGE/{p=$3} /искомое/{print p": "$0}' doc.txt`
  и открой её через `Read` с `pages: "N-N"`.

## 4. Отчёт обратно в PDF

Владелец просит материалы в PDF. Собирай HTML и печатай headless-хромом:

```bash
bash .claude/skills/pdf-analysis/scripts/html2pdf.sh report.html "Отчёт.pdf"
```

Хром лежит в `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`, кириллицу
закрывает DejaVu Sans. Каркас вёрстки — `templates/report_a4.html` в этом же навыке:
A4, поля 14/12 мм, шрифт 9 pt, тёмно-синие заголовки, таблицы с зеброй.

Обязательная проверка перед отправкой: открой готовый PDF через `Read` с `pages`
и посмотри на вёрстку. Типовые дефекты:
- инлайновый `style="width:34%"` в первой строке таблицы перебивает CSS и растягивает
  колонки на треть страницы;
- `page-break-before: always` оставляет полупустые страницы — ставь его только там,
  где действительно нужен разрыв;
- двухколоночный список делай через `column-count: 2`, а не через flex: flex не
  балансирует колонки и вываливает хвост на следующую страницу.

Готовый файл отдавай через `SendUserFile` (`display: "render"`).

## 5. Порядок для типовой задачи «разбери пакет ТЗ»

1. `pdfinfo` по всем файлам — страницы, размер.
2. `pdftotext -l 3` — проверка текстового слоя.
3. OCR папки.
4. Первая страница каждого документа: что за машина, ЕНН, объект, кто утвердил.
5. Попарный дифф одинаковых позиций по разным объектам — расхождения исполнений
   это главная находка для закупки (один лот против двух).
6. Проверка находок глазами по страницам.
7. Сборка HTML → PDF → `SendUserFile`.
