# Логика использования системы ОВЭ-75 (UX-спека)

Принцип: сайт — рабочий инструмент команды, не витрина. Каждый экран отвечает
на один вопрос одного человека. Текст потоком — справочник, работа — карточками.

## Персоны и их вопросы
| Кто | Вопрос | Экран |
|---|---|---|
| Владелец | что требует моего решения; успеваем ли; что изменилось | Штаб |
| Инженер | что делать; где входы; куда сдать; что дальше | Задачи |
| Любой | дай документ X версии Y | Документы |
| Читающий | почему принято решение Z | Справочник (текстовые вкладки) |

## Экраны
1. **Штаб** — первый экран: готовность (компактно), «требуют решения» (очередь
   владельца), 3 ближайшие вехи Ганта, сводка последней ревизии. Без скролла.
2. **Задачи** — очередь карточек из bi_docs (status=task/base), Ганта (crit и
   ближайшие), подачи (form/team). Фильтры: роль, лот. Карточка: задача → входы
   (кнопки файлов) → критерий готовности → куда сдать. Сдача: чат проекта;
   статус в базе обновляет куратор (сайт статический — это осознанно).
3. **Документы** — дерево папок (Лот 1..4, Общее, Подача, ТКП, Спецификации,
   Эскизы): строка = документ: статус · последняя версия · скачать · история
   (личные версии из ревизий Р0/Р1/Р2 с пометками изменён/новый). ZIP по папке.
   Полная таблица ревизий — в свёрнутом «Архиве» внизу (для сверки срезов).
4. **Справочник** — ПЗ по разделам, расчёты, реестры, аналитика. Из задач сюда
   ведут ссылки; сюда приходят читать, не работать.

## Правила
- Кнопка скачивания одна и та же везде: ⬇ + метка типа; никаких россыпей в тексте.
- Версии живут у документа, ревизии-срезы — механика архива, не главный UI.
- Новый контент сначала попадает в базу (json) → сборка раскладывает по экранам.
- «Закрыть вопрос» = изменить статус в базе (через куратора) → пропадает из
  очереди, появляется в «изменилось за ревизию».
