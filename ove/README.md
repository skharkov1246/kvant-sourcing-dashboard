# ОВЭ-75 — сайт проекта «обжиг – выщелачивание – электроэкстракция»

Разбор тендерного пакета **АО «Кольская ГМК»** по строительству комплекса ОВЭ
производительностью **75 000 т катодной меди в год** (г. Мончегорск, промплощадка КГМК).

Один самодостаточный HTML (встроенные CSS+JS, без внешних ресурсов), **10 вкладок**:
Обзор · Этапы · Блоки и лоты · Оборудование · Поставщики · Автоматизация ·
Мировой опыт · Китай · Торги за БИ · Стройка · CAPEX.

## Что разобрано

Исходный пакет — «ТЗ на БИ ОВЭ-75. v.3.6.docx» + 7 приложений:

| № | Приложение | Что взято на сайт |
|---|---|---|
| — | ТЗ на БИ v3.6 | 4 лота, границы проектирования, состав БИ, требования к стоимости |
| 1 | ИД, часть 1 (пирометаллургия) | сырьё, продукты обжига, табл. 24 (оборудование), НЗП, табл. 26 (нормы расхода) |
| 2 | ИД, часть 2 (гидрометаллургия) | катодная медь, схемы цепи аппаратов, табл. 4.1 и 4.2 (оборудование), табл. 8.5 и 9.5 (расходы) |
| 3 | Электроснабжение и электрооборудование | состав раздела ЭС в БИ |
| 4 | Требования ЦИМ | этапы ЦИМ, ПИМ, форматы IFC, российский BIM-стек |
| 5 | Требования ОАСУ | АСУТП / весоизмерение / СПТ / ПГС + утверждённые производители (на 03.08.2026) |
| 6 | Здание ЦЭМ (11 листов) | под размещение Лота №3 |
| 7 | Здание ГМУ (10 листов) | под размещение Лота №2 |

Таблицы 4.1 и 4.2 в исходном .docx — внедрённые EMF (объекты Excel); текст извлечён
разбором записей `EMR_EXTTEXTOUTW` напрямую из EMF, LibreOffice эти файлы не открывает.

## Структура

```
ove/
  data/project.json      проект, площадка, сырьё, продукция, режимы, предыстория
  data/lots.json         9 объектов комплекса, 4 лота БИ, границы, состав документации
  data/equipment.json    70 позиций оборудования по лотам + вне-БИ периметр
  data/flowsheet.json    технологическая цепочка по операциям и материальные потоки
  data/stages.json       жизненный цикл БИ → ЦИМ → ОТР → ПД → РД → поставка → СМР → ПНР
  data/resources.json    нормы расхода реагентов и энергоресурсов, дутьевой режим
  data/automation.json   требования ОАСУ + утверждённые Заказчиком производители
  data/world.json        мировой опыт, аналоги, поставщики по классам оборудования
  data/china.json        китайские EPC и производители, дыры, playbook
  data/tender.json       подготовка к торгам: чеклист ТЗ, риски, стратегия, план действий
  data/capex.json        модель CAPEX (AACE Class 5) с параметрами
  data/suppliers.json    26 закупочных позиций: кандидаты Мир / КНР / РФ, что спрашивать
  data/bitrix_ove.json   выгрузка из Bitrix24 (сид; живая — в CI)
  tools/bitrix_ove.py    выгрузка поставщиков ОВЭ-75 из Bitrix24 → data/bitrix_ove.json
  site/index.template.html  шаблон (плейсхолдеры __..._JSON__)
  build.py               сборка → ove/public/index.html
  public/index.html      собранный сайт (артефакт сборки, закоммичен для просмотра)
```

## Сборка и проверка

```bash
python3 ove/build.py            # → ove/public/index.html
```

Проверка перед PR — headless Chromium (Playwright): все 10 вкладок открываются, нет
JS-ошибок, нет горизонтального оверфлоу (в т.ч. на 390px), работают фильтры оборудования
и параметры расчёта CAPEX.

## Данные: правила честности

- Технологические цифры — из ТЗ и ИД Заказчика, без пересчёта и без округления «на глаз».
  Где ИД даёт два варианта (дутьё), показаны оба.
- Внешние факты о компаниях — со ссылкой на первоисточник и датой проверки (13.08.2026).
  Где кандидат не подтверждён — прямо написано «уточнить», список не добивается наугад.
- Имена в колонках Мир / КНР / РФ — **кандидаты для запроса**, а не поставщики.
  Подтверждение = полученное ТКП.
- **CAPEX — оценка порядка величины (AACE Class 5, −30 %…+50 %), не смета.** В тендерном
  пакете нет ни одной цены: получение ТКП от 2–3 поставщиков на каждую позицию и есть
  предмет работы Исполнителя БИ. Каждая строка модели помечена основанием и уверенностью.
- Bitrix-блок пустой, пока не прошла живая выгрузка — это честнее, чем показывать
  выдуманные данные.

## Деплой

Отдельный проект Cloudflare Pages **kvant-ove** → `kvant-ove.pages.dev`, открытый доступ.
Публикуется workflow `.github/workflows/ove-deploy.yml`; триггер — изменения `ove/**` в `main`.
Свой домен привязывается в панели Cloudflare (Pages → kvant-ove → Custom domains).

Перед сборкой workflow пытается обновить `data/bitrix_ove.json` живой выгрузкой из Bitrix24
(секрет `BITRIX_WEBHOOK_URL`). Если секрета нет или Bitrix недоступен — берётся сид,
сборка не падает.
