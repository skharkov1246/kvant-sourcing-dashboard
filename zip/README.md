# База ЗИП — снабжение / прайс / ODM

Внутренний веб-инструмент по ЗИП подземной горной техники (перфораторы Epiroc/Atlas Copco,
Sandvik Tamrock, Caterpillar, Normet). По каждой позиции — китайские **ODM-производители**
для импортозамещения, статусы поставщиков, **цены конкурентов / таможенная статистика**,
**чертежи**, и связка с Bitrix. Живёт на Cloudflare Pages: **https://kvant-zip.pages.dev**
(проект `kvant-zip`). Данные — в Supabase; сайт офлайн-фолбэком читает вшитый снимок (SEED).

Этот каталог — восстановленный из задеплоенного сайта исходник (прошлая сессия деплоила
напрямую через wrangler, в git код не попадал). Теперь всё под контролем git.

## Структура

```
zip/
  data/positions.json       752 позиции (снимок для SEED/офлайна)
  data/odm_suppliers.json   ~4.3k ODM-записей китайских заводов
  data/price_records.json   цены конкурентов / таможня по годам (наполняется)
  site/index.template.html  исходник сайта; SEED вставляется в плейсхолдер [/*__SEED__*/]
  site/vendor/supabase.js   самохостинг supabase-js v2 (без CDN)
  site/_worker.js.example   опциональный пароль-гейт (по умолчанию сайт открыт)
  supabase/migrations.sql   таблицы price_records, drawings + Storage-бакет + RLS
  build.py                  сборка zip/public/index.html из шаблона и данных
```
`zip/public/` — артефакт сборки, в git не хранится (`.gitignore`).

## Сборка и локальный просмотр

```bash
python zip/build.py            # → zip/public/index.html (+ vendor/)
# открыть zip/public/index.html в браузере: работает офлайн на SEED,
# в режиме «● офлайн-копия» правки/загрузки не сохраняются (нужен Supabase).
```

## Данные и БД (Supabase)

Проект Supabase: `vpjliavuuxjcvtxbthlp`. URL и **publishable**-ключ вшиты в сайт (это
не секрет — ключ для анонимного клиента). Таблицы:
- `positions`, `odm_suppliers`, `rfq_requests`, `change_log` — были ранее;
- `price_records`, `drawings` + Storage-бакет `drawings` — добавляет `supabase/migrations.sql`.

**Применить миграции** (один раз):
- GitHub → Actions → **ZIP base — apply DB migrations** → Run workflow.
  Нужен секрет репозитория `SUPABASE_DB_URL` (Supabase → Settings → Database → Connection
  string, URI). Идемпотентно.
- **Или** вручную: Supabase → SQL Editor → вставить `supabase/migrations.sql` → Run.

## Деплой

Автоматически: push в `main`, затрагивающий `zip/**`, запускает workflow
**ZIP base deploy** → `build.py` → `wrangler pages deploy zip/public --project-name=kvant-zip`.
Использует те же секреты, что дашборд: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`.
Ручной запуск — Actions → ZIP base deploy → Run workflow.

## Рабочая таблица снабжения (Google Sheets → база)

Котировки поставщиков и карта производителей из рабочей Google-таблицы
импортируются в базу скриптом `zip/tools/import_sheet.py`:
- источник — снимок `zip/tools/sources/kvant_sourcing_sheet.xlsx` (обновить:
  `curl -sSL "https://docs.google.com/spreadsheets/d/<ID>/export?format=xlsx" -o zip/tools/sources/kvant_sourcing_sheet.xlsx`);
- «File A» → реальные котировки (WMS/Mindrill/YLF в USD, KAT/Sanshan/Fuxuan в
  CNY) в `price_records` (source=«КП поставщика (таблица снабжения)»), привязка
  по OEM PN к позиции; «Производители по позициям» → `data/sheet_meta.json`
  (группа, применение COP, кандидаты-производители, пробники) — блок
  «🏭 Снабжение» в карточке позиции. Идемпотентно; после — `python zip/build.py`.

## Таможня glbs.io (обновление статистики)

Actions → **ZIP customs — glbs.io recon/pull** → Run workflow:
- `mode=pull`, `method=search` — бесплатно, **лимит не тратит**; отдаёт участников,
  страны, даты, описания и **USD/кг**; денежные суммы (инвойс/тамож.) маскируются.
- `method=save` — открывает реальные суммы (G42 инвойс в валюте, G46 стат.стоимость
  USD), но обнуляет вес/USD-кг и **не содержит количество штук** (цена только за
  строку декларации). У ключа режим `full` — списание лимита не наблюдалось.
- Крупные HS (>100k поставок/запрос отклоняются) дробить входами
  `period_start/period_finish` по годам. `hs` — 4–10-значные префиксы через запятую.
- Ключ: секрет `GLBS_API_KEY` **или** вход `api_key` (маскируется в логах;
  приватный репо). После выгрузки ключ стоит перевыпустить.
- Результат `zip/customs/out/customs_*.json` коммитится; далее локально
  `python zip/tools/aggregate_customs.py` → `data/customs_market.json` + `price_records`,
  пересборка `build.py`.

## Возможности сайта (сорсинг-ERP для локализации производства)

Путь детали: поиск поставщика → RFQ → заказ образца → склад и тест → квалификация → серия.

- **Позиции** (752): поиск, фильтры (категория/OEM/**локализация**/**критичность**/Bitrix/с‑без ODM/
  **«ждёт действия»**), сортировка, колонки «Локализация» и «Обр.» (число образцов). Карточки
  грузятся лениво (быстрый первый рендер).
- **Карточка позиции:**
  - **📋 Локализация (master data)** — статус воронки, критичность (ABC), ответственный,
    годовая потребность, срок, MOQ, целевая цена;
  - **💶 Цены конкурентов/таможня** — добавление/правка строк;
  - **🧪 Образцы** — жизненный цикл заказ→в пути→склад→тест→одобрен/брак, ячейка хранения,
    результат теста, фото (Supabase Storage);
  - **📐 Чертежи** — загрузка/скачивание файлов;
  - **ODM-заводы** — стадия/качество/RFQ + **скоркарта** (цена/качество/срок/связь/сертификаты)
    и контакты (email/WeChat/тел/Incoterms/оплата/сертификаты).
- **Склад** — доска всех образцов с фильтром по статусу, ячейки/склад, переход к позиции.
- **Спрос** — потребление и бюджет заказчика (ПАО «ГМК «Норильский никель», ЗФ: СПГТ):
  лимиты снабжения перфораторов по годам, OEM-разбивка, **импортная (локализуемая) часть
  бюджета в €**, и прайс конкурента-локализатора (АО «Машиностроительный холдинг», ~510
  позиций) — бенчмарк по цене/срокам. Источник — Excel-лимиты (`zip/tools/parse_demand.py`
  → `data/demand.json`, `data/competitor_prices.json`; обновляются раз в год новым лимитом).
- **Таможня** — таможенная статистика импорта ЗИП/перфораторов в РФ из **glbs.io**
  (Глобус-ВЭД, официальный API): ~22 тыс. деклараций по HS 8431/8412/8207/8467 за
  2023–2026 — импорт по годам/странам, топ импортёров-конкурентов (локализатор
  АО «Машиностроительный холдинг» подсвечен, отдельный блок наблюдения), топ
  экспортёров-заводов, бенчмарк **USD/кг**, и раскрываемый **прямой импорт от OEM**
  (Sandvik/Epiroc/Atlas Copco). Совпадения по нашему каталожному № (strong) уходят
  в цены соответствующей позиции. Источник — `zip/customs/glbs_pull.mjs` (workflow
  **ZIP customs**) → `customs_*.json` → `tools/aggregate_customs.py` →
  `data/customs_market.json` + `price_records`.
- **Материалы** — стратегия «крепче оригинала»: по каждому изнашиваемому узлу перфоратора
  марка/обработка OEM (Epiroc/Sandvik/Tamrock) vs наша превосходящая альтернатива (сталь/сплав
  + термо/поверхностная обработка), шорт-лист **поставщиков материалов** (спецстали, твердый
  сплав, суперсплавы, покрытия, поковки, РТИ, металлургия РФ, Индия/Корея/Турция —
  ~130 компаний с контактами) и по каждому узлу — раскрываемая **техкарта
  термо/ХТО** (цементация/закалка/крио/отпуск/азотирование/дробеструй с числовыми
  режимами) и **протокол приёмочных испытаний** (ISO/ASTM/EN/ГОСТ, критерии), плюс
  полный текст стратегии. Источник — research-workflow; данные в
  `data/material_strategy.json`, `data/material_process.json`,
  `data/material_suppliers.json`, `СТРАТЕГИЯ-МАТЕРИАЛЫ.md`.
- **Обзор** — KPI (ждут действия, локализовано, образцы, покрытие), воронка локализации,
  образцы по статусам, топ разброса цен (потенциал экономии), покрытие по категориям.
- **Поставщики** — группировка заводов (один RFQ на пакет позиций) + средний балл скоркарты.
- **Журнал** изменений.
- Экспорт в Excel/CSV: позиции, ODM (+скоркарта/контакты), цены, **образцы**, поставщики.
- Онлайн-режим (`● онлайн`) — правки пишутся в Supabase для всей команды; офлайн-копия —
  только просмотр вшитого снимка.

## Безопасность

Сайт открыт (без логина) — по решению владельца. Включить пароль: скопировать
`site/_worker.js.example` → `zip/public/_worker.js` и задать `BASIC_AUTH_PASS` в Pages.
Запись в БД идёт по anon-ключу — чувствительные операции при необходимости сузить через
RLS в `supabase/migrations.sql`.

## Обновление снимка (SEED)

Снимок в `data/*.json` — офлайн-фолбэк. Освежить из живой БД можно экспортом из Supabase
(или кнопками «⬇ Excel» на сайте) с последующей конвертацией в JSON того же формата и
пересборкой. Боевой сайт всегда показывает актуальные данные напрямую из Supabase.
